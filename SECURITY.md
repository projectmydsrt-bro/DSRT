# Security Policy for DSRT.js

## 1️⃣ Supported Versions

| Version | Supported          |
|---------|------------------|
| 1.x     | ✅ Supported       |
| 0.x     | ⚠️ Deprecated     |

Please ensure you are using a supported version before reporting security issues.

---

## 2️⃣ Reporting a Vulnerability

If you discover a **security vulnerability** in DSRT.js, please report it **privately** to the maintainers:

- **Email:** security@dsrt.io  
- **PGP Key (optional):** [Insert PGP public key here]  

**Do NOT post security issues publicly** (e.g., GitHub Issues) before a fix is released.

Include in your report:

- Detailed description of the vulnerability  
- Steps to reproduce the issue  
- Impact assessment (e.g., crash, data leak, remote code execution)  
- Environment / browser / OS / device information  

---

## 3️⃣ Response and Disclosure Policy

- We will acknowledge receipt of the report within 48 hours  
- Critical issues will be prioritized and patched ASAP  
- A coordinated disclosure will be done after the fix is released  
- Credit will be given to the reporter in release notes, unless requested otherwise  

---

## 4️⃣ Best Practices for Contributors

- Do not commit secrets or API keys to the repository  
- Validate input and outputs when working with DSRT.js engine  
- Follow coding standards and review PRs for potential vulnerabilities  
- Keep dependencies up-to-date and monitor for known security issues  

---

## 5️⃣ Security Updates

- Security updates will be published in the **CHANGELOG.md** or release notes  
- Users should always update to the latest **stable version**
